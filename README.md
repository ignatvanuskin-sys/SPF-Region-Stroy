# СПФ Регион Строй — сайт и система обработки заявок

Сайт и внутренняя система для компании «СПФ Регион Строй» (Астана): окна ПВХ,
алюминиевые окна, фасадные витражи, входные двери, перегородки, остекление
балконов. Реализовано по мастер-промпту: публичный сайт, приём и обработка
заявок, уведомления в Telegram, админка, аналитика.

Стек: **Next.js 15 (App Router) + TypeScript + Tailwind CSS v4**, хранилище —
**PostgreSQL** (продакшн) или локальный файл (разработка). Без проприетарных
зависимостей: схему БД можно перенести на любой хостинг.

---

## ⚠️ Прочитайте до деплоя

**Без базы данных заявки не сохраняются надёжно.** На serverless-платформах
(Vercel, Netlify, AWS Lambda) рабочий каталог доступен только для чтения, и файлы
не переживают перезапуск инстанса. Приложение в этом случае не падает — оно
автоматически переключается на временный каталог, сайт и формы работают, но:

- заявки, настройки и галерея **исчезают** после перезапуска инстанса;
- загруженные фото видны только тому инстансу, который их принял.

Для реальной работы обязательны две переменные: **`DATABASE_URL`** и
**`SESSION_SECRET`**. Подробнее — [docs/RISKS.md](docs/RISKS.md).

## Быстрый старт локально

```bash
npm install
npm run dev
```

Сайт откроется на http://localhost:3000. База не нужна: включится файловое
хранилище (`./data/store.json`).

Создать владельца админки и загрузить начальные настройки:

```bash
# .env: ADMIN_BOOTSTRAP_EMAIL, ADMIN_BOOTSTRAP_PASSWORD
npm run admin:create
npm run db:seed
```

Админка: http://localhost:3000/admin → редирект на форму входа.

## Продакшн с PostgreSQL

```bash
# .env: DATABASE_URL, SESSION_SECRET, CRON_SECRET, SITE_URL, TELEGRAM_*
npm run db:migrate     # применить схему (идемпотентно)
npm run db:seed        # начальные настройки
npm run admin:create   # владелец админки
npm run build && npm start
```

Драйвер переключается автоматически: как только задан `DATABASE_URL`,
приложение работает через PostgreSQL (`lib/db/pg-store.ts`).

```

                     работы, отзывы, о компании, для организаций, контакты,
                     FAQ, политика
  admin/             админка: login + (dash) — обзор, заявки, замеры, галерея,
                     отзывы, утверждения, ссылки и QR, журнал, настройки, пароль
  api/               leads, events, measurements(+availability), uploads,
                     telegram/webhook, admin/{export,qr,files}, cron/*
components/
  ui/                примитивы интерфейса (shadcn-подход: cva + Tailwind)
  site/              шапка, подвал, секции страниц, мобильная панель, карта
  forms/             быстрая заявка, мастер расчёта, запись на замер, B2B
  admin/             формы поверх серверных действий
lib/
  domain/            бизнес-логика: заявки, статусы, замеры, цены, SLA,
                     атрибуция, утверждения, настройки, уведомления
  db/                интерфейс хранилища + драйверы pg и json + schema.sql
  notify/            каналы уведомлений (Telegram, e-mail, webhook) и шаблоны
  telegram/          бот: команды, кнопки, дайджест, напоминания
content/             тексты и данные компании (единственный источник правды)
scripts/             migrate, seed, create-admin, smoke, verify-admin
tests/               модульные и интеграционные тесты
```

Ключевой принцип: **бизнес-логика в `lib/domain` не знает о транспорте**. Её
вызывают и HTTP-маршрут, и Telegram-бот, и cron. Поэтому добавить WhatsApp-бота
в фазе 2 можно, не переписывая ядро.

## Как работает обработка заявки

1. Клиент отправляет форму → `POST /api/leads`.
2. Проверки: origin, лимит по IP, honeypot и тайминг, Turnstile (если настроен),
   валидация zod, лимит по телефону.
3. **Сначала запись в БД**, потом уведомления. Заявка не может потеряться из-за
   сбоя Telegram.
4. Идемпотентность по `submissionId`: двойной клик не создаёт дубль.
5. Дедупликация: тот же телефон за 24 часа → к существующей заявке добавляется
   событие «повторное обращение».
6. Уведомление уходит сразу (outbox) и повторяется cron'ом при сбое. Если
   Telegram недоступен — запасное письмо и красная пометка в админке.

## Роли и доступ

| Роль | Права |
|------|-------|
| `owner` | всё: настройки, утверждения, удаление данных клиента, экспорт |
| `manager` | заявки, замеры, галерея, назначение ответственных |
| `viewer` | только просмотр |

Сессия — HMAC-подписанная httpOnly-cookie на 7 дней. Пароли — только bcrypt.

## Reestr утверждений (важно)

`content/claims.ts` — механизм, не дающий опубликовать непроверенный факт.
На сайте показывается только подтверждённое: сроки, гарантия, бренды, цены и
режим работы не выдуманы, а заменены нейтральными формулировками до тех пор,
пока владелец не ответит в разделе «Утверждения» админки. Ответ появится на
сайте сразу, без деплоя.

По умолчанию **цены выключены** (`PRICE_DISPLAY=off`): в ответе API нет ни
одного числа расчёта.

## Настройка бота Telegram

1. Создайте бота у `@BotFather` → `TELEGRAM_BOT_TOKEN`.
2. Добавьте бота в служебный чат → `TELEGRAM_LEADS_CHAT_ID` (поможет `@userinfobot`).
3. Зарегистрируйте webhook:
   ```bash
   curl "https://api.telegram.org/bot<TOKEN>/setWebhook" \
     -d "url=https://<домен>/api/telegram/webhook" \
     -d "secret_token=<TELEGRAM_WEBHOOK_SECRET>" \
     -d 'allowed_updates=["message","callback_query"]'
   ```
4. Добавьте сотрудников в админке («Настройки») и передайте им код — сотрудник
   пишет боту `/start КОД`.

Команды бота: `/new`, `/my`, `/today`, `/week`, `/stats`, `/find`, `/help`.

## Запланированные задачи (cron)

Все эндпоинты требуют заголовок `Authorization: Bearer $CRON_SECRET`.

| Эндпоинт | Назначение | Рекомендуемая частота |
|---|---|---|
| `/api/cron/tick` | очередь уведомлений + SLA + напоминания о замерах | каждые 5 мин (Pro) |
| `/api/cron/digest` | утренний дайджест, 09:00 Asia/Almaty | раз в сутки |
| `/api/cron/sla` | только контроль SLA | каждые 5 мин |
| `/api/cron/measure-reminders?when=tomorrow` | напоминания накануне | раз в сутки |
| `/api/cron/review-reminders` | просьба об отзыве после монтажа | раз в сутки |

На бесплатном тарифе Vercel частота cron — раз в сутки; это учтено: основное
уведомление уходит сразу при создании заявки, cron остаётся страховкой.

## Аналитика и персональные данные

- Источник и UTM хранятся 30 дней (`?src=` побеждает реферер) — это то, что
  делает рекламу управляемой. QR-коды со ссылками с метками генерируются в
  админке («Ссылки и QR»).
- Сторонние счётчики (Метрика, GA4, Meta) подключаются **только** после согласия
  посетителя. Свои события обезличены: путь, имя события, id сессии.
- В логах телефон маскируется (`+7701***6787`). Файлы клиентов лежат вне
  публичного каталога и отдаются только через защищённый маршрут.
