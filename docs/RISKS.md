# Ограничения и что нужно перед продакшном

Честный список того, что реализовано не полностью или требует решения владельца.
Файл существует, чтобы эти пункты не выяснились в день запуска.

---

## 1. Хранилище данных — критично

| Условие | Драйвер | Годится для продакшна |
|---|---|---|
| Задан `DATABASE_URL` | PostgreSQL | **Да** |
| Не задан | JSON-файл (`lib/db/json-store.ts`) | Нет |

Файловый драйвер создан, чтобы проект запускался одной командой без базы. Он
корректен для локальной работы и демонстрации, но у него есть принципиальные
границы:

- **Serverless.** Рабочий каталог доступен только для чтения, поэтому приложение
  автоматически пишет во временный каталог. Заявки и настройки **исчезают** после
  перезапуска инстанса. Признак эфемерного хранилища виден в админке.
- **Несколько реплик.** Каждая реплика держит свой файл — данные расходятся.
- **Очередь записи** (`tx`) работает только внутри одного процесса; при
  параллельных процессах возможна потеря изменений.

**Что сделать:** арендовать PostgreSQL (Neon, Supabase, Railway, собственный
сервер), задать `DATABASE_URL`, выполнить `npm run db:migrate`. Схема написана на
обычном SQL без проприетарных расширений — переносится куда угодно.

## 2. Ограничитель частоты — в памяти процесса

`lib/rate-limit.ts` считает лимиты в памяти. Это работает для одного инстанса.
При нескольких репликах (или на serverless, где инстансы разные) лимит по IP
слабоват: поток можно распределить между инстансами.

**Что сделать:** при росте нагрузки вынести счётчики в Redis. Лимит по телефону
дополнительно проверяется по базе (3 заявки в час), и это работает независимо от
реплик.

## 3. Файловое хранилище — локальный диск

Загрузка фото галереи и чертежей работает локально (`lib/storage.ts`). На
serverless это означает: файл виден только тому инстансу, который его принял.

**Что сделать:** подключить S3-совместимое хранилище или Vercel Blob. Сейчас в
`/api/uploads` стоит явная проверка: если драйвер не `local`, маршрут возвращает
понятную ошибку с предложением прислать файл в WhatsApp — молча терять файлы он не
будет. Для оптимизации изображений стоит установить `sharp` (без него файлы
сохраняются как есть, о чём админка честно сообщает).

## 4. Юридические документы

`/politika` — **рабочий шаблон, а не юридический документ.** Нужно:

- проверить текст у юриста;
- определить срок хранения данных (в тексте стоит 12 месяцев как ориентир);
- уточнить требования законодательства РК к размещению персональных данных
  (возможное требование хранить базу на территории Казахстана — от этого зависит
  выбор хостинга и региона базы);
- публиковать реквизиты (БИН) только после подтверждения — сейчас блок скрыт.

## 5. Непроверенные утверждения

По замыслу сайт не публикует неподтверждённые факты. Поэтому до заполнения
раздела «Утверждения» на сайте **нет**: сроков изготовления и монтажа, гарантии,
брендов профилей, цен, режима работы, года основания, состава команды, условий для
организаций.

Это не баг, а защита от недостоверной информации в рекламе. Но пока эти пункты не
заполнены, сайт выглядит сдержанно, а часть вопросов клиентов уходит менеджеру.

**Что сделать:** пройти чек-лист в админке. Владельцу понадобится 20–30 минут.

## 6. Контент

- **Фотографии работ.** Галерея пуста: мы не берём фото из 2ГИС и Instagram —
  у площадок и авторов есть права на контент. Блок «Наши работы» на сайте не
  показывается, пока владелец не загрузит свои снимки.
- **Дословные отзывы.** Публикуются только с согласия авторов. Пока их нет,
  показывается рейтинг 2ГИС и обобщение тем.
- **Логотип.** Сейчас используется графический знак «оконная рама» (SVG). Если
  есть фирменный логотип — его нужно загрузить вместо знака.

## 7. Запись на замер — без SMS-подтверждения

Клиент выбирает слот, но это **запрос**, а не подтверждённая запись: статус
`pending`, менеджер подтверждает кнопкой в Telegram. Без SMS-подтверждения
подделать запись может кто угодно, поэтому честнее оставить подтверждение
менеджеру. Автоматическое подтверждение по номеру телефона — задача фазы 2.

## 8. Что не реализовано (фазы 2–3 по мастер-промпту)

- **Казахская версия** сайта (`KK_ENABLED`). Флаг есть, переводы отсутствуют.
- **AI-ассистент** на сайте (`AI_ASSISTANT_ENABLED`).
- **Страница статуса заказа** для клиента по номеру заявки
  (`ORDER_STATUS_PAGE_ENABLED`). Публичная страница статуса создаёт риск утечки:
  подбор номера заявки не должен раскрывать чужие данные, поэтому её нужно
  проектировать отдельно (код + телефон, ограничение попыток).
- **WhatsApp Business API** — сейчас WhatsApp открывается человеком по кнопке.
  Это осознанно: автоматические рассылки требуют согласия и шаблонов.
- **Интеграция с CRM** — есть универсальный webhook (`LEAD_WEBHOOK_URL`),
  конкретные коннекторы (Bitrix24, amoCRM) не написаны.
- **Восстановление пароля** — сброс делает администратор вручную, письма для
  сброса не настроены.
- **E2E-тесты в браузере** (Playwright) — конфигурация и сценарии не написаны;
  вместо них работают 71 модульный/интеграционный тест и 36 дымовых проверок,
  которые покрывают поток заявки целиком.

## 9. Мелкие технические долги

- `docs/QA.md` и `docs/SEO.md` (чек-лист приёмки и план продвижения) не написаны —
  на них есть ссылки в коде.
- Экспорт CSV выгружает до 5000 заявок за раз; для больших объёмов нужна
  постраничная выгрузка.
- Изображения галереи отдаются через защищённый маршрут, но без CDN: для сайта с
  большим числом фото потребуется кэширование на краю сети.

## 10. Переменные, без которых продакшн не работает

| Переменная | Зачем | Что будет без неё |
|---|---|---|
| `DATABASE_URL` | хранение заявок | данные исчезнут при перезапуске инстанса |
| `SESSION_SECRET` | подпись сессии админки | вход в админку падает с ошибкой (в продакшне) |
| `SITE_URL` | canonical, sitemap, QR-коды | QR и ссылки будут вести на localhost |
| `CRON_SECRET` | защита `/api/cron/*` | cron-эндпоинты отвечают 401 |
| `TELEGRAM_BOT_TOKEN` + `TELEGRAM_LEADS_CHAT_ID` | уведомления менеджеру | заявка сохранится, но менеджер не узнает |

Остальное (`RESEND_API_KEY`, `TURNSTILE_SECRET_KEY`, счётчики аналитики, S3) —
опционально, без них система работает в урезанном, но предсказуемом режиме.
